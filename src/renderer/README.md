# React ledger

`App.tsx` composes navigation, hash routes, keyboard commands and update view restoration.
`store.tsx` subscribes before fetching, serializes invalidations, coalesces refreshes and accepts monotonically increasing generations. `model.ts` normalizes retained input, preserves unchanged plan objects by revision and keeps recorded stages separate from checklist progress. `preferences.ts` stores only private navigation preferences under the existing `wb-*` keys.

All native and data operations use `AgentOpsClient` (`client.ts`) over `AgentOpsBridge` from `src/shared/contracts`. The preload exposes method-specific Result/Empty calls, validates responses/events and strips Electron event objects. Main handlers are owned by the main-process integration task. No renderer module reads a file, writes a plan or registers an IPC handler.

The work views are Summary (`/`), List (`/list`), Board (`/board`), Timeline (`/timeline`), Needs attention and Archive. Summary puts checklist progress and agent workload above fixed-height Current work and Recent activity panels; Show more reveals further entries inside those panels. Task counters and per-card Tasks links open List directly with the matching filters. Plan states remain available in a collapsed section. Board groups plans by recorded stage and lets the owner explicitly choose a Plan state through the icon picker or a card drop. These actions reuse the guarded Status-only writer, backups and 2-minute Undo; checklist task statuses never change. Board pins are independent of state. Timeline shows recorded daily activity and the latest file edit, ordered by the latest plan or agent update. All views use the existing shell, theme tokens, archive and confirmed Recycle Bin actions.

The sidebar has a pointer- and keyboard-operable resize separator (185–420 logical pixels), bounded by the viewport; double-click resets it. Plan cards in the sidebar can be dragged or moved with Alt+Up/Down within their workspace in All and Starred collections; Recent stays ordered by last opened. Sidebar width, sidebar card order, tab order, up to eight pinned tabs and Board pins live only in the private navigation preference. Up to eight unpinned tabs remain open in addition to pins. Tab drag and Move left/right reorder within the pinned or unpinned group. Pinning a tab protects it from automatic eviction and hides Close until unpinned. Board pins and sidebar ordering never alter files or Plan state. Plan pages keep Goal and Next compact above the section tabs and place Waiting for owner / Blocked notes alongside questions in the Questions tab.

Visual styling follows Orca's neutral semantic surfaces, Geist typography, compact controls, quiet separators and the beta's 1400px Summary width. The bundled, unmodified Geist variable font matches the Orca desktop font; its upstream SIL Open Font License is included in `public/fonts/Geist-OFL.txt`. Font files are served locally under the existing `font-src 'self'` policy, with no remote font requests.

List has a compact checklist overview with instant status filters and a segmented distribution. Counts follow the search, Work, selected Plans and agent filters, but remain stable while switching task status. Group headers show the full plan's checklist distribution; the sidebar keeps just the combined Done + In progress count, percentage and a compact attention indicator. The combined figure uses `(done + doing) / total` consistently across List and sidebar, with an explicit tooltip and accessible label. Individual status counters and segments still report their own counts; the combined figure does not mean completed. The recorded Plan state stays separate. Explicit `[waiting]` tasks are supported alongside Done, In progress, To do and Blocked; legacy Partial remains distinct. Blocked counts take priority over the existing plan-level Needs attention indicator. Attention uses the existing stale, question and report rules, without inventing task completion or a new agent inactivity threshold. Segment tooltips expose counts and percentages on hover and, in List, keyboard focus.

`agents.ts` derives the coordinator and executors from optional plan, run and step fields. A step report must match the source line, text and milestone; a reused line cannot inherit unrelated results. The run's `active` flag alone drives Working now. Missing participation, results and report timestamps stay blank. Plan-page agents share the task's title row; source metadata, Open plan folder and Copy link are in its action menu. Snapshot reuse compares runs as well as the file revision, so a new report appears without a plan-file edit. The agent query filter persists across work tabs; List filters the agents actually reported on each task. Initial rendering is bounded to 200 tasks, 100 plans per Board column and 100 Timeline plans, with keyboard-accessible controls to show the rest. Set `AGENT_OPS_SCREEN_DIR` when running the agent-view Electron tests to export light/dark screenshots to a chosen folder; otherwise they stay in the test output.

For the independently testable interface, open `#/?fixture=demo&theme=light` (or `theme=dark`) in the built app and reload once. Other explicit sample modes are `setup`, `empty`, `hidden`, `loading`, `error`, `update` and `large` (more than one page of List tasks). A visible **Sample workspace** badge identifies the in-memory bridge. It never calls the real bridge for its data/native actions. Its mode remains in session storage while navigating; clear `agent-ops-ui-fixture` from session storage and remove the fixture query to return to the real bridge. The default app uses the real bridge and shows an actionable error until main modules are connected.

Run the repository npm checks. Vitest covers the state model, component output, contracts and fixture services; `npm run smoke` runs the Electron interface flows in isolated temporary profiles. Playwright fixtures reload through Electron's main-owned navigation API, keeping navigation denial enabled. No browser download or real AI profile is needed.

The original `vscode:` document launch is represented by a read-only source document/file label. The final IPC contract authorizes folder choices and fixed release/PR targets, and has no arbitrary file/URI opener. Add a separately reviewed main-resolved source-file target before restoring a document-launch action; do not construct one from renderer `root`, `file` or `spec` strings.
