# Agent Ops development

Agent Ops is a Windows desktop reader built with Electron, React and TypeScript.
Read README.md, INSTALL.md and docs/release-readiness.md before release work.

- Keep the app a reader. Agents record their own runs through the report command (`--report`, append-only files under `<data folder>/runs`) and the plan fields `Agent:` and `<!-- Executors: ... -->`; the app only reads them. It never assigns work or infers acceptance states from runs. Orchestration belongs to Orca. The sole content edit is the owner's explicit Plan-state change (owner decision 2026-11-12, extending Mark as Done from 2026-11-11): the icon picker, a Board drop, or Mark as Done replaces only the value of the top `Status:` line with a value in shared `PLAN_STATES`, every other byte unchanged. Its guards: the file is resolved from the plan key like Archive/Delete, never from a path the window sends; its bytes must match the revision the owner saw, checked again just before the atomic rename; the original is first copied to `<data folder>/backups/plan-edits` (newest 50 kept); read-only config and the busy gate refuse it; no `Status:` line means no write; Undo restores the original for 2 minutes only while the file still holds what the action wrote. Checklist task statuses never change with Plan state. Sidebar card ordering, tab ordering, tab pins, Board pins and sidebar width are private navigation preferences; pinning or reordering never moves files or changes Plan state. Archive/Unarchive changes app settings only; confirmed Delete goes to the Windows Recycle Bin, never permanent deletion.
- For Mark as Done, the top `Status:` is the first case-insensitive English label before the first level-2 to level-4 heading, outside fenced or indented code. A legacy `Trạng thái:` alone never authorizes a write. Both Mark as Done and Undo re-resolve the current plan and folder containment before replacement. Undo tokens live in memory and do not survive restart. As with Delete, a write in the small interval between the final check and rename remains an accepted race; no cross-process lock is claimed.
- Plans live at `<TasksDir>/<workspace>/<plan>.md`; configured workspace plan folders can still be read. A move into Tasks is a separate owner-requested Settings action: keep a backup, never overwrite and report every file.
- `tasksDir` is a setting. Skills read `AGENT_OPS_TASKS` or `<data folder>/tasks-dir.txt`, and `AGENT_OPS_REPORT` or `<data folder>/report-command.txt` for the report command, never a baked-in machine path. Only the verified installed app changes the user environment values; the report command takes no single-instance lock, opens no window and registers nothing. File and config names are English.
- The single canonical skill is `skills/task-plan/SKILL.md`, embedded at build time. Write Skills or AI client instructions only on the owner's action (the Claude Code session hooks below are the one exception), with backups, atomic replacement and hash/marker guards. Preserve unrelated text and locally changed files. An app update never installs Skills automatically.
- Sessions (owner decision 2026-11-13): AI client sessions record presence, todos and handoff notes through `--hook` (Claude Code hooks) and `--handoff` (any agent), append-only under `<data folder>/sessions`; the app only reads them and never infers acceptance from them. The verified installed app keeps its hooks in Claude Code settings (`~/.claude/settings.json` and each Orca profile's `settings.json`) without a click while Settings > Sessions is on, and removes them when it is off: only handlers marked `agent-ops-hooks-v1` change, invalid JSON is left alone, each change is backed up to `<data folder>/backups/claude-settings` and written atomically. Hook commands always exit 0 and print only SessionStart context. Development, tests and smoke never touch real AI client settings.
- Main owns files/native actions/updates; preload exposes named typed methods; React has no Node. Keep sandbox, contextIsolation, strict CSP, sender/top-frame/payload/result validation and denied navigation/new windows. Add no HTTP server or general command, file or URL executor.
- Preserve `%LOCALAPPDATA%/AgentOps/config.json` and unknown keys. Newer/unreadable config stays read-only. Stop only verified beta executable paths before shared data writers start; retain recovery backups/journals. Go is retired; its quirks are not acceptance criteria. Frozen fixtures remain regression tests.
- Tests use temporary data, plans and AI profiles. Never use real data, AI client config, registry or the installed app. Inject OS effects. Ordinary development/smoke must not register startup/protocols or send real notifications. Never commit private plans, logs or profiles.
- Validate with `npm ci`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run smoke`, `npm run package` and `npm run smoke:packaged`. Real install/uninstall, picker, Recycle Bin restore and published-release update checks require a disposable Windows account/VM. Packaging never runs the installer.
- Development uses `.dev-data` or temporary `AGENT_OPS_DATA_DIR`. Sample/test modes are disabled in packaged apps. Release drafts require review; do not push or publish without an instruction.
- User-facing language is Workspace / Skills / Tasks. Explain problems plainly. Speak to the owner in concise Vietnamese; code comments and documentation are English.

Business hierarchy and richer problem/impact briefs remain separate work. Do not invent acceptance states or rewrite historical evidence.
